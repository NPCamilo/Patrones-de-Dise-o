Lección 4: State vs Strategy

Cuál elegir según quién decide el comportamiento y cuándo combinarlos

Dos primos, una sola pregunta

State y Strategy se parecen estructuralmente, pero responden a una pregunta distinta: ¿quién decide el comportamiento?

Python 3 · Estándar · 15 min

¿Por qué esta lección ahora?

Es la confusión más común al aprender State. Ambos patrones delegan en objetos separados, pero la intención y el dueño de la decisión difieren. Saber distinguirlos evita sobre-ingeniería en tus proyectos.

1. La pregunta clave que las separa

¿Quién decide el comportamiento?

State

El objeto mismo, según su estado interno. El cliente no elige; el objeto transita solo.

Strategy

El cliente, desde afuera. Elige qué algoritmo usar y se lo inyecta al contexto.

2. Comparativa directa

AspectoStateStrategy
¿Quién decide? El objeto, por su estado interno El cliente, al construir el contexto
¿Cambia en tiempo de ejecución? Sí, el objeto transita entre estados Generalmente no, el cliente lo fija
¿Quién cambia el comportamiento? El ConcreteState actual El cliente, al asignar una nueva estrategia
Estructura Contexto + interfaz de estado + estados concretos Contexto + interfaz de estrategia + estrategias concretas
Ejemplo clásico Pedido: Pendiente → Pagado → Enviado Cálculo de descuento: Regular, Premium, VIP

3. Strategy en Python — el cliente elige

Un carrito de compras donde el cliente elige la estrategia de descuento al pagar.

from __future__ import annotations
from abc import ABC, abstractmethod


# ---- Strategy: interfaz de descuento ----
class Descuento(ABC):
    @abstractmethod
    def aplicar(self, monto: float) -> float:
        ...


# ---- ConcreteStrategy ----
class DescuentoRegular(Descuento):
    def aplicar(self, monto: float) -> float:
        return monto  # sin descuento


class DescuentoPremium(Descuento):
    def aplicar(self, monto: float) -> float:
        return monto * 0.90  # 10 % descuento


class DescuentoVIP(Descuento):
    def aplicar(self, monto: float) -> float:
        return monto * 0.80  # 20 % descuento


# ---- Context ----
class Carrito:
    def __init__(self, descuento: Descuento) -> None:
        self.descuento = descuento  # El cliente lo elige

    def pagar(self, monto: float) -> float:
        final = self.descuento.aplicar(monto)
        print(f"Monto original: ${monto:,.2f} → Final: ${final:,.2f}")
        return final


# ---- Uso: el CLIENTE elige la estrategia ----
if __name__ == "__main__":
    carrito_regular = Carrito(DescuentoRegular())
    carrito_regular.pagar(1000)   # $1000.00

    carrito_premium = Carrito(DescuentoPremium())
    carrito_premium.pagar(1000)   # $900.00

    carrito_vip = Carrito(DescuentoVIP())
    carrito_vip.pagar(1000)       # $800.00

4. ¿Cuándo combinar State y Strategy?

No son excluyentes. Puedes usar State para modelar el ciclo de vida de un objeto y, dentro de cada estado, usar una Strategy para variar un algoritmo específico.

Escenario combinado

Un envío cambia de estado (Pendiente → EnTránsito → Entregado) y, en cada estado, el cálculo de costo usa una estrategia distinta según el tipo de paquete.

Regla práctica

Si el comportamiento cambia solo por el estado interno → usa State. Si el comportamiento lo elige el cliente → usa Strategy. Si necesitas ambas cosas → combínalas.
