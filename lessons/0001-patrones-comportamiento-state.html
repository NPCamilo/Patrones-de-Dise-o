Lección 1: Patrones de comportamiento y State

Curso de patrones de diseño · Foco en comportamiento · Ejemplos en Python

¿Qué resuelve State?

Permite que un objeto cambie su comportamiento cuando su estado interno cambia, sin llenar el código de condicionales imposibles de mantener.

Python 3 · Estándar · Sin dependencias

¿Por qué esta lección ahora?

Ya viste que los patrones se dividen en tres familias: creacional, estructural y comportamiento. Esta lección se queda solo con la tercera y te muestra por qué State es uno de sus miembros más útiles para exponer y para implementar en proyectos reales.

1. Los tres tipos de patrones (repaso rápido)

FamiliaQué resuelveEjemplos
Creacional Cómo crear objetos sin acoplarse a clases concretas Singleton, Factory Method, Builder, Prototype, Abstract Factory
Estructural Cómo componer clases y objetos para formar estructuras más grandes Adapter, Decorator, Proxy, Composite, Bridge, Flyweight, Facade
Comportamiento Cómo se comunican y reparten responsabilidades los objetos State, Strategy, Observer, Command, Mediator, Memento, Visitor
Los patrones de comportamiento no hablan de cómo se construye el código, sino de cómo fluye la lógica de negocio. Ahí es donde más se nota la diferencia entre código difícil de mantener y código flexible.

2. Qué es State en una frase

State permite que un objeto cambie su comportamiento cuando su estado interno cambia. Parece que el objeto cambió de clase, pero en realidad delega en un objeto de estado diferente.

Analogía: una máquina expendedora. Es la misma máquina, pero su comportamiento depende de si tiene dinero insertado, si ya dispensó el producto, o si está sin dinero.

3. State vs Strategy (la confusión más común)

AspectoStateStrategy
¿Quién decide el comportamiento? El objeto mismo, según su estado interno El cliente, desde afuera
¿Cambia durante la ejecución? Sí, el objeto transita entre estados Generalmente no, el cliente lo fija
¿Cuándo usarlo? Cuando el comportamiento depende de un estado que el objeto gestiona solo Cuando el comportamiento lo elige el usuario o el cliente

4. Tu primera victoria tangible — Estado de un pedido en Python

Imagina un Pedido que pasa de Pendiente a Pagado y luego a Enviado. Sin State terminarías con if/else en cada método. Con State, cada estado vive en su propia clase.

from __future__ import annotations
from abc import ABC, abstractmethod


# ---------------------------------------------------------------------------
# Interfaz State
# ---------------------------------------------------------------------------
class EstadoPedido(ABC):
    @abstractmethod
    def pagar(self, pedido: "Pedido") -> None:
        ...

    @abstractmethod
    def enviar(self, pedido: "Pedido") -> None:
        ...

    @abstractmethod
    def cancelar(self, pedido: "Pedido") -> None:
        ...


# ---------------------------------------------------------------------------
# ConcreteState: Pendiente
# ---------------------------------------------------------------------------
class Pendiente(EstadoPedido):
    def pagar(self, pedido: "Pedido") -> None:
        pedido.estado = Pagado()
        print("Pago aceptado. Pedido ahora está pagado.")

    def enviar(self, pedido: "Pedido") -> None:
        print("No se puede enviar: el pedido aún no se ha pagado.")

    def cancelar(self, pedido: "Pedido") -> None:
        pedido.estado = Cancelado()
        print("Pedido cancelado antes de pagar.")


# ---------------------------------------------------------------------------
# ConcreteState: Pagado
# ---------------------------------------------------------------------------
class Pagado(EstadoPedido):
    def pagar(self, pedido: "Pedido") -> None:
        print("El pedido ya está pagado.")

    def enviar(self, pedido: "Pedido") -> None:
        pedido.estado = Enviado()
        print("Pedido enviado al cliente.")

    def cancelar(self, pedido: "Pedido") -> None:
        print("No se puede cancelar: ya se envió o está pagado.")


# ---------------------------------------------------------------------------
# ConcreteState: Enviado
# ---------------------------------------------------------------------------
class Enviado(EstadoPedido):
    def pagar(self, pedido: "Pedido") -> None:
        print("Ya se envió el pedido. No se puede pagar.")

    def enviar(self, pedido: "Pedido") -> None:
        print("El pedido ya fue enviado.")

    def cancelar(self, pedido: "Pedido") -> None:
        print("No se puede cancelar un pedido ya enviado.")


# ---------------------------------------------------------------------------
# ConcreteState: Cancelado
# ---------------------------------------------------------------------------
class Cancelado(EstadoPedido):
    def pagar(self, pedido: "Pedido") -> None:
        print("El pedido está cancelado. No se puede pagar.")

    def enviar(self, pedido: "Pedido") -> None:
        print("El pedido está cancelado. No se puede enviar.")

    def cancelar(self, pedido: "Pedido") -> None:
        print("El pedido ya está cancelado.")


# ---------------------------------------------------------------------------
# Context
# ---------------------------------------------------------------------------
class Pedido:
    def __init__(self) -> None:
        self.estado: EstadoPedido = Pendiente()

    def pagar(self) -> None:
        self.estado.pagar(self)

    def enviar(self) -> None:
        self.estado.enviar(self)

    def cancelar(self) -> None:
        self.estado.cancelar(self)


# ---------------------------------------------------------------------------
# Prueba
# ---------------------------------------------------------------------------
if __name__ == "__main__":
    p = Pedido()
    p.pagar()   # Pago aceptado. Pedido ahora está pagado.
    p.enviar()  # Pedido enviado al cliente.
    p.pagar()   # Ya se envió el pedido. No se puede pagar.
    p.cancelar()  # No se puede cancelar un pedido ya enviado.
